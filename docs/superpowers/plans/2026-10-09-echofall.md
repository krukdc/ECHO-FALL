# ECHO//FALL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a complete keyboard-controlled neon action-RPG in one locally runnable HTML file.

**Architecture:** Keep the deliverable dependency-free in `index.html`, with separated CSS and JavaScript sections. JavaScript owns a single explicit screen/run state, a requestAnimationFrame simulation, keyboard state, world entities, combat/progression systems, and canvas/HUD rendering.

**Tech Stack:** HTML, CSS, Canvas 2D, vanilla JavaScript, Web Audio API.

**Spec:** `docs/superpowers/specs/2026-10-09-echofall-design.md`

## Global Constraints

- One local `index.html`; no framework, server, installation, external dependencies, or downloaded assets.
- All game actions must be possible with the keyboard; mouse is not required.
- Use delta time with a safe maximum and `requestAnimationFrame`.
- Resize canvas while preserving the game state; pause or suppress simulation when the tab is hidden.
- Restart must clear all entities, timers, stats, upgrades, and pressed keys.
- Provide five floors with two waves per floor, a weapon selector, route/shop/risk choices, persistent records, a three-phase boss, pause, death, victory, and restart screens.

## Review Focus

- Repeated keydown must not repeat menu selections, attacks, or confirmations; exercise edge-triggered input and held movement.
- Simultaneous directional inputs and aim changes must not produce invalid movement or target vectors; inspect diagonal movement and four aim directions.
- Resizing during combat or changing device pixel ratio must preserve centered rendering and keyboard control; resize at multiple window sizes.
- Returning from a hidden tab must not apply a large delta or damage the player; hide and restore during a wave.
- Restart from death and victory must start equivalent clean runs; reach both endings and compare initial HUD and entities.
